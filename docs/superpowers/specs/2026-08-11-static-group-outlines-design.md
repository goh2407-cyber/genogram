# 同住框與生活圈不受人物文字影響

日期：2026-08-11
狀態：使用者已核准

## 目標

人物姓名與備註可透過八方向按鈕自由微調，但文字位置不得改變同住框或
生活圈的線條、命中區與匯出幾何。

## 現況與根因

- `GenogramCanvas.getHouseholdBounds()` 目前把每位成員的文字 bounds 加入同住框
  hull。修改 `Person.labelPlacement` 後，文字 bounds 改變，因此同住框會重算並移動。
- 生活圈由使用者建立的固定 `points` 描述，現行繪製、命中與匯出不依賴人物文字；
  這部分不需要改動，但要加入回歸測試防止未來耦合。

## 方案比較

1. **符號座標專用（採用）**：同住框只使用人物符號的上下左右邊界；人物移動時
   框線仍正常更新，只有文字移動時完全不變。生活圈維持既有固定點。
2. **建立後凍結框線（不採用）**：文字不會影響線條，但人物移動後框線也不更新，
   會造成框線與成員分離。
3. **快取或延遲重算（不採用）**：只能減少跳動，下一次重算仍會受到文字影響，
   沒有真正解除資料耦合。

## 設計

### 文字區與人物符號分開點擊

- 點擊人物姓名或備註的文字 bounds 時，選取該人物並進入「文字調整情境」。
- 文字調整情境直接顯示既有八方向與重置控制，但不顯示人物符號旁的快速新增功能圈。
- 點擊人物符號時維持現行選取語意與快速新增功能圈。
- 使用八方向按鈕調整後保留文字調整情境，功能圈不得因重新 render 而出現。
- 點擊畫布空白、其他人物或切換工具時退出文字調整情境。
- 文字 bounds 必須遵循目前 View 設定；被隱藏的姓名或備註不可形成可點擊熱區。

### 同住框

- `getHouseholdBounds()` 的 hull 輸入只使用成員人物符號：
  `x ± personSize / 2`、`y ± personSize / 2`，保留既有輪廓 padding。
- 不再呼叫 `getPersonLabelGeometry()` 擴張同住框。
- `drawHouseholds()`、`isPointOnHouseholdBoundary()`、內容 bounds 與 PNG/JPEG 匯出
  繼續共用 `getHouseholdBounds()`，確保畫面、點擊與匯出一致。
- 人物座標改變時仍即時更新同住框；只改 `labelPlacement` 時框線完全不動。

### 生活圈

- 不修改資料模型與繪製演算法。
- 繪製、命中與匯出繼續只使用 `lifeCircle.points`。
- 人物文字微調不得寫入或重算 `lifeCircle.points`。

### 資料與歷史

- 不新增欄位，不需資料遷移。
- 文字微調仍只寫入 `Person.labelPlacement`，Undo/Redo 行為不變。
- 同住框與生活圈資料在文字微調前後必須 byte-identical。

## 驗收測試

新增真實瀏覽器回歸：

1. 建立含兩位成員的同住框及一個生活圈。
2. 記錄同住框 bounds/hull、生活圈 points、人物座標。
3. 用正式人物文字微調流程改變一位成員的 `labelPlacement`。
4. 確認文字幾何確實移動。
5. 確認同住框 bounds/hull、生活圈 points、人物座標完全不變。
6. 確認同住框畫面與命中使用同一份不變幾何，匯出無錯誤。
7. 跑 `verify_hh_lc.js`、手動文字控制、匯出與三副本同步回歸。

另加入文字命中互動回歸：

1. 真實滑鼠點擊姓名或備註後，人物被選取且屬性面板顯示文字位置控制。
2. 文字點擊與後續文字微調均不顯示快速新增功能圈。
3. 點擊人物符號後快速新增功能圈仍正常顯示。
4. 隱藏姓名／備註後，原文字位置不再命中人物文字。
5. 點擊空白或切換人物後清除文字調整情境。

## 非目標

- 不改人物文字按鈕、步進距離或儲存格式。
- 不自動搬移文字。
- 不改生活圈手動拖曳或同住框拖曳語意。
- 不改關係線、人物符號與臨床線型。
