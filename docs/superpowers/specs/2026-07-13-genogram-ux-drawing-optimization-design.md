# 家系圖介面與繪製優化設計

日期：2026-07-13
工作分支：`codex/genogram-ux-drawing-optimization`

## 1. 目標

在不改變專業線條顏色、臨床符號語意、資料格式相容性與匯出一致性的前提下，讓社工與心理專業人員在一般筆電及大螢幕上更容易建立、對齊、閱讀與編輯家系圖。

本次優化聚焦三項成果：

1. 降低介面認知負擔，讓畫布取得更多空間。
2. 讓新增人物像把棋子放入格位一樣直覺、整齊且可預期。
3. 改善複雜圖面的選取、拖曳、文字可讀性與局部整理，不採用黑箱式全圖自動排列。

## 2. 不可變更事項

- 保留現有 Logo；其餘介面可重新設計。
- 不修改任何既有專業關係線顏色。
- 不修改方形、圓形、三角形、死亡 X、案主、同性別及其他臨床符號語意。
- 親子方向固定為 `from=parent, to=child`，不得以 Y 座標推論親屬方向。
- 保持既有 JSON 往返相容、Undo/Redo、快捷鍵與匯出格式。
- 螢幕與匯出沿用同一套繪製核心；純互動 overlay 不進入匯出。
- 不更換 Canvas 技術，不導入 SVG/WebGL 或圖片式人物渲染重寫。
- 根目錄、`geno/` 與 `refactor/app/` 的程式副本依專案規則同步；`geno/index.html` 的本地資源差異仍保留。

## 3. 設計方向：臨床分析工作區

### 3.1 頂部全域列

頂部列只保留跨工具的全域操作：Logo、檔案名稱、Undo/Redo、儲存、匯出與說明。低頻功能收進「更多」選單，避免所有按鈕同時競爭注意力。

### 3.2 畫布工具列

將選取、新增人物、建立關係、範圍圈選、同住框與生活圈組成畫布左上角的緊湊工具列。工具列不得遮住主要人物；在窄版筆電上可折疊成主要工具加展開選單。

### 3.3 情境式右側面板

右側面板可完全收合，並分成三頁：

- **屬性**：依目前選取的人物、關係、同住框或生活圈顯示對應欄位。
- **圖例**：容納完整專業符號與線型，預設不長期展開。
- **檢視**：控制姓名、年齡、備註、醫學標記、情感關係、同住框與生活圈的畫面顯示。

大螢幕預設展開，筆電依可用寬度收合。面板狀態只屬於使用者介面，不寫入個案資料。

### 3.4 快速親屬操作

父母、伴侶、手足與子女的快速新增入口仍貼近已選人物。只有人物被選取時才出現，並維持按鈕優先命中，避免與底下人物或線條爭奪點擊。

### 3.5 視覺系統：安定臨床

最終介面採用「安定臨床」方向，目標是高階醫療／研究軟體的精準感，加上社福工作需要的溫度。專業感來自比例、留白、字級與互動一致性，不依賴裝飾性漸層或大量特效。

- **色彩**：以暖白、霧灰與深墨藍建立介面層級；勵馨桃紅 `#ed1261` 僅用於 Logo、主要動作、目前工具、選取焦點與吸附提示。不得更動畫布上的專業關係線顏色。
- **字體**：優先使用既有本地 Noto Sans TC 資源。標題、欄位標籤、資料內容與輔助文字建立固定字級和字重，不使用全域粗體製造層級。
- **間距**：採 8px 基準的 spacing system；控制項、面板、工具群和頁面邊界使用一致倍數，避免零碎間距。
- **形狀**：小型控制項使用克制圓角，面板與浮層使用較大圓角；同類元件共享相同高度、邊框與內距。
- **深度**：邊框負責區隔靜態區域，陰影只用於浮動工具、選單、對話框及拖曳物件。不得為每個卡片都加陰影。
- **動態**：hover、focus、選取、展開與收合使用 120–180ms 的短動畫；遵守 `prefers-reduced-motion`。不使用循環動畫或純裝飾進場效果。
- **可及性**：文字與控制項符合 WCAG AA 對比；鍵盤 focus ring 清楚可見；圖示按鈕具備文字提示與可讀標籤；一般點擊目標至少 36px，主要工具以 40px 為準。
- **品牌呈現**：保留現有 Logo，不重畫識別。桃紅在大面積介面中保持稀少，讓主要動作與選取狀態真正突出。

工具列、側欄、輸入欄位、分頁、狀態提示、選單與對話框必須由同一組 CSS design tokens 驅動，避免各區塊各自定義近似但不一致的顏色、圓角和陰影。

## 4. 智慧格位放置

本功能協助使用者「放得準」，不替使用者重新決定整張圖的排列。

### 4.1 共用座標規則

- 重用現有 `CELL_WIDTH`、輩分列與 `computeDragSnap()`，不建立第二套格線座標系統。
- 人物以標準格位為主要落點；同輩優先位於同一列。
- 自由文字、同住框與生活圈保持自由座標。
- 使用者可按輔助鍵暫時略過吸附，處理特殊臨床配置。

### 4.2 新增人物流程

1. 使用者選擇人物類型。
2. 畫布顯示半透明人物預覽與候選格位。
3. 滑鼠移動時顯示 X/Y 對齊、格位是否被占用及可能建立的關係線。
4. 點擊後人物落格並建立所需關係。
5. Esc 取消；Undo 可完整回復新增人物與關係。

一般「新增人物」以游標附近最近空格為建議；不強制推開既有人物。

### 4.3 快速新增親屬的候選格位

- 父母：上一輩列，優先以目前人物為中心形成父母中點。
- 伴侶：同列相鄰空格，依左右可用空間選擇。
- 手足：同列左右最近空格，並維持父母中點鏡像與等距規則。
- 子女：下一輩列，優先靠近父母中點；單親則靠近該人物中心。

若首選格位被占用，按照同列距離由近到遠搜尋空位；找不到時顯示預覽但不自動搬移其他人物。

### 4.4 局部整理

框選人物後可使用「同輩對齊」「等距排列」及「整組移動」。操作只作用於選取範圍，先提供預覽，確認後寫入一筆 history。取消不得留下部分座標變更。

既有全圖自動排列保留相容性，但不作為本次主流程，也不擴充成強制棋盤重排。

## 5. 繪製與可讀性改善

### 5.1 語意縮放

依縮放倍率調整非必要文字密度：

- 遠景：保留人物符號、姓名與主要家庭結構。
- 中景：加入年齡與重要狀態。
- 近景：顯示備註、醫學標記及完整關係文字。

此功能只影響畫面顯示。預設匯出完整內容；若未來提供「依目前檢視匯出」，必須由使用者明確選取。

### 5.2 焦點模式

選取人物時，可透過 render-time overlay 標示本人、父母、伴侶、子女及直接關係。原線條顏色不變；非焦點內容僅降低畫面強度。overlay 不進入匯出，也不寫入資料。

### 5.3 標籤避碰

建立共用標籤配置流程，優先順序為：姓名、年齡／狀態、婚姻日期與關係說明、一般備註。日期與關係文字沿實際路徑尋找安全位置；空間不足時備註折行或縮成摘要，選取後顯示完整內容。

標籤位置不得改變線條幾何與命中測試；螢幕與匯出使用相同的最終配置結果。

### 5.4 穩定拖曳線路

拖曳人物期間保留目前婚姻線路拓撲，只更新必要端點；放開後才重新評估 auto 模式的ㄇ／一／ㄩ最終路徑。手動 `routeMode` 永遠優先，不得被拖曳覆寫。

### 5.5 導覽與輔助

- 提供可收合的小型導覽圖，顯示整張圖與目前 viewport。
- 可選擇顯示淡化的輩分導引帶；它不參與親屬推論且不進匯出。
- 棋盤格位、占用提示、吸附線與焦點光暈皆為互動 overlay。

導覽圖與輩分帶屬第二階段功能；若第一階段已充分解決操作問題，可延後而不阻擋上線。

## 6. 顯示層與匯出

「檢視」頁可暫時切換姓名、年齡、備註、醫學標記、情感關係、同住框及生活圈。顯示層預設不改個案資料，也不改標準匯出內容。

生活圈仍於 render 步驟 0.5 繪製在最底層；同住框、人物、關係線、選取工具與互動按鈕的既有 z-order 和 hit-test 規則保持一致。

## 7. 程式邊界

- App 負責工具狀態、選取狀態、格位候選與 history 交易。
- `computeDragSnap()` 延伸為可供新增預覽重用的純計算入口。
- Canvas 接收候選格位、焦點集合、顯示層與拖曳路徑快照，負責繪製而不自行推論親屬。
- `KinshipEngine` 是父母、子女、祖先與後代查詢的唯一來源。
- `personMap` 仍是人物查找的唯一索引；任何 persons 增刪改依規則同步。
- 標籤配置與路徑幾何各自維持單一真相，供 draw、export 與 hit-test 重用。

## 8. 錯誤與邊界處理

- 自己連自己、非法伴侶或非法親子連接要提供清楚狀態訊息，不建立部分資料。
- 新增人物取消、格位預覽取消與局部整理取消都不得寫入 history。
- 新增人物加關係、整組移動及局部整理各自只寫一筆 history。
- 被占用格位只提供替代建議，不自動推開、刪除或覆蓋人物。
- 顯示層、焦點模式或語意縮放失效時，安全退回完整顯示。

## 9. 分階段實作

### 第一階段：介面骨架與人物落格

- 重整全域列、畫布工具列及三頁情境面板。
- 實作面板響應式收合。
- 實作人物半透明預覽、候選格位、占用提示及取消流程。
- 讓四種快速親屬新增使用智慧格位。

### 第二階段：畫布可讀性

- 焦點模式與檢視層。
- 語意縮放。
- 穩定拖曳線路。
- 標籤避碰。

### 第三階段：大型圖面工具

- 局部對齊與等距排列。
- 小型導覽圖。
- 可選輩分導引帶。

每一階段獨立提交、獨立驗收；未經使用者確認不得合併到 `main`。

## 10. 驗收與測試

### 視覺不變式

- 現有 16 張 golden-image 中，專業線色與臨床符號不得出現非核准差異。
- 新增智慧格位、焦點 overlay、語意縮放及標籤避碰 fixture。
- overlay 不得出現在 PNG/JPEG/SVG/PDF 匯出。

### 邏輯與互動

- 既有 `verify_drag.js`、`verify_fixes.js`、`verify_hh_lc.js`、`verify_marriage_geom.js`、`verify_roundtrip.js` 全數通過。
- 新增測試覆蓋四種親屬候選格位、格位占用、取消、自由放置與單筆 history。
- 覆蓋筆電寬度與大螢幕寬度，驗證面板不遮擋主要畫布操作。
- 驗證拖曳中路徑穩定，放開後 auto 路由正確，手動 routeMode 不被覆蓋。

### 效能

- 以現有 benchmark 比較變更前後；100 人／200 關係的拖曳與縮放保持順暢。
- 不為假設性效能問題導入 rAF 重構或新渲染框架。只有量測顯示瓶頸時，才考慮離屏 Canvas 快取或 viewport culling。

## 11. 完成定義

- 使用者能在筆電與大螢幕上更快找到主要工具，並可收起右側面板。
- 新增人物與快速新增親屬能預覽並落入合理格位，無須全圖自動排列。
- 大型圖面可透過焦點、顯示層及語意縮放降低雜訊。
- 線條顏色、臨床符號、資料往返、Undo/Redo、快捷鍵與匯出均無回歸。
- 所有變更停留在功能分支，經使用者實際確認後才討論合併 `main`。
