# 家系圖安全走線與輕微校正設計

日期：2026-07-13
狀態：使用者已核准操作方向與技術架構，等待書面規格確認
目標分支：`codex/genogram-ux-drawing-optimization`

## 1. 背景與問題

目前人物可自由拖曳並在放開時吸附到輩分列。當人物被拖到密集、同列、上下顛倒或父母與子女垂直距離不足的位置時，家庭線幾何會出現下列問題：

- 親子主幹被迫越過子女後再折回，形成突出或回頭線。
- 父母姓名與備註被視為無條件的垂直障礙，即使主幹 X 座標沒有穿過文字，也會把主幹往下推，壓縮子女走線空間。
- 快速建立父母固定使用 120px 間距，附近人物或較寬文字可能占用中央走廊。
- `drawFamilies()` 與 `getRelationshipPath()` 各自重算部分幾何，增加繪製、命中、高亮與匯出不一致的風險。
- 現有補救規則主要依個別症狀追加，缺少統一、可測試的路徑規劃結果。

本設計採用使用者選定的 B 方案：「輕微校正＋智慧走線」。系統先嘗試在人物原位置產生乾淨路徑，只有所有安全候選都失敗時才微調目前拖曳者；既有人物不因他人的走線需求而被移動。

## 2. 設計目標

1. 任意拖曳後，親子線仍維持可預測、正交且可判讀的幾何。
2. 正常上下代配置優先採用由父母往子女單調前進、不折返的路徑。
3. 線段不得穿過無關人物符號、姓名或備註的實際外框。
4. 快速建立父母時保留父母組合完整性，並預留中央親子走線走廊。
5. 螢幕繪製、命中判定、選取高亮及所有匯出共用相同路徑。
6. 原有臨床符號、關係線型、顏色、虛線間距與方向語意完全不變。
7. 微調是拖曳交易的一部分，只新增一筆 Undo；按住 `Alt` 可保留精確落點。

## 3. 非目標

- 不自動重新排列整張家系圖。
- 不更改 `Relationship.getLineStyle()`、臨床顏色或符號語意。
- 不以 Y 座標推斷父母／子女方向；親屬語意仍只由 `KinshipEngine` 與正規化後的 `from=parent, to=child` 決定。
- 不移動與目前操作無關的既有人物。
- 不將完整通用圖形路由函式庫引入目前的原生 Canvas 架構。
- 不為同住框或生活圈新增位置校正；它們只作為走線避障資訊。

## 4. 使用者操作行為

### 4.1 一般人物拖曳

1. 拖曳期間以目前虛擬位置建立人物外框、文字外框及家庭走線候選。
2. 若原位置有安全路徑，人物位置不再額外改動。
3. 若原位置無安全路徑，依序測試同輩分列的 `x - 60` 與 `x + 60`。只接受能降低碰撞且不占用人物格的候選。
4. 額外水平校正上限為 `GRID.CELL_WIDTH / 2`，目前即 60px；Y 維持放開後所屬的輩分列。
5. 兩側候選都不安全時，人物維持原落點，改採側邊繞行，不進行更大幅位移。
6. 按住 `Alt` 放開時跳過額外位置校正，但仍使用最佳可用走線。

拖曳期間可顯示半透明預測人物、桃紅校正方向與安全走廊提示。這些提示只存在於互動畫面，不進入 PNG、JPEG、SVG 或 PDF 匯出。

### 4.2 整組拖曳

同住框的剛性拖曳維持現有行為，不逐人校正，也不破壞成員相對位置。路徑規劃器只重算線路。

### 4.3 快速建立父母

1. 父母是固定共同移動的剛性組合，中心優先對齊子女。
2. 先以目前 120px 父母中心間距評估人物碰撞、文字碰撞及中央走廊。
3. 若 120px 無法保留安全走廊，僅對新建父母組擴展為 180px。
4. 依既有確定性順序搜尋組合中心：原中心、左側一格、右側一格、再向外擴展。
5. 每個候選同時評估兩位父母位置與三條預覽關係；選擇第一個無人物碰撞且具有安全親子主幹的候選。
6. 新建父母、婚姻線及兩條親子線仍以單一 history transaction 提交；既有人物位置不得改變。

## 5. 路徑規劃架構

### 5.1 `FamilyRoutePlanner`

在 `js/domain/` 新增純計算元件 `FamilyRoutePlanner`，位置與 `KinshipEngine` 並列。規劃器不繪圖、不寫入人物資料、不操作 history。

輸入包含：

- 已由 `KinshipEngine` 分組完成的父母與子女。
- 婚姻線的實際共用幾何與可掛接水平段。
- 人物符號外框、姓名外框、備註外框及安全 margin。
- 親子關係的 `linkType`、雙胞胎／多胞胎資訊。
- 與目前縮放無關的世界座標走線常數。

輸出包含：

- 路徑模式：`normal-trunk`、`side-lane`、`same-row` 或 `reversed`。
- 實際來源連接埠與主幹掛接點。
- 主幹、手足橫桿、每位子女分支及多胞胎連線的點序列。
- 每條關係 ID 對應的命中／高亮路徑。
- 安全性診斷：碰撞、垂直折返、無效端點及建議的拖曳 X 校正量。

### 5.2 外框與連接埠

- 人物符號使用實際 50px 圖形外框，外加 10px 安全 margin。
- Canvas 呼叫端先以 `measureText()` 與實際行高建立姓名、備註矩形，再將矩形傳入規劃器；空白文字不產生障礙，規劃器本身不依賴 Canvas API。
- 路徑只在其來源／目標人物的指定連接埠穿越該人物外框，其餘人物外框皆不可穿越。
- 正常親子線由婚姻線可見水平段或單親底部連接埠出發，子女在下方時接子女頂部；子女在上方時接子女底部。
- 端點離開人物或婚姻線後先保留最短直線段，再進行第一次轉彎，避免貼邊尖折。

### 5.3 有限候選路徑

路徑搜尋採固定候選集合，不使用無上限網格搜尋：

1. **中央主幹**：從父母掛接點垂直到安全橫桿，再水平分支至子女。
2. **偏移主幹**：在子女中心附近選擇不穿過外框的垂直走廊。
3. **左右側邊走廊**：中央區域被阻擋時，繞到家庭邊界左側或右側再返回目標。
4. **同列路徑**：父母與子女同列時，從符號側邊走正交 L／ㄇ形，不穿過符號中心。
5. **反向路徑**：子女被拖到父母上方時，每位父母至子女使用方向一致的反向 L 型，不共用會穿越人物的正常主幹。

候選評分順序為：

1. 無效端點或穿越障礙：淘汰。
2. 垂直方向折返：高額懲罰。
3. 與其他結構線不必要交叉：懲罰。
4. 轉彎數。
5. 總長度。
6. 左右同分時採固定左側優先，確保結果不因陣列順序改變。

此策略參考固定節點避障路由與正交單調路徑概念，但限制為家系圖所需的少數候選，以維持 Canvas 即時拖曳效能：

- [ELK Libavoid：固定節點的正交走線](https://eclipse.dev/elk/blog/posts/2022/22-11-17-libavoid.html)
- [yFiles：正交與單調路徑限制](https://docs.yworks.com/yfiles/doc/developers-guide/orthogonal_edge_router.html)
- [GoJS：避開節點、連接埠與端點直線段](https://gojs.net/latest/learn/links)

## 6. 繪製與資料流程

1. `App.render()` 注入 `personMap`、關係及必要互動預覽。
2. Canvas 以 `KinshipEngine` 取得已正規化的家庭分組。
3. Canvas 建立人物與文字外框，呼叫 `FamilyRoutePlanner.planFamily()`。
4. `drawFamilies()` 只依規劃結果繪製線型與裝飾。
5. `getRelationshipPath()`、選取高亮及鉛筆位置直接讀取同一規劃結果，不再複製幾何公式。
6. 螢幕與所有匯出路徑都使用相同規劃器；互動提示在 export flag 下完全略過。

為避免拖曳期間重複計算無關家庭，可依家庭成員座標、文字內容、關係 ID／型別與婚姻 route mode 建立穩定 signature。signature 不變時重用規劃結果；任何相關人物位置、文字或關係變動即失效。

## 7. 路徑不變量

每個規劃結果必須符合：

1. 所有座標皆為有限數值，不可產生 `NaN` 或 `Infinity`。
2. 每條分支起點與終點落在正確連接埠或婚姻水平段。
3. 線段不得越過目標人物邊界後再折回，因此不會在人物另一側突出。
4. 正常上下代關係的垂直段不得反向折返。
5. 除來源／目標端點外，線段不得穿越人物符號或文字障礙內部。
6. `parent-child` 的 `linkType` 只影響既有指定線段；親生、收養、寄養語意保持不變。
7. 多胞胎 V 型與同卵橫桿語意保持不變。
8. 相同輸入必須產生完全相同的點序列。

## 8. 失敗與退化處理

- 關係端點不存在：跳過該關係並保留既有資料清洗行為，不讓 render 例外。
- 沒有婚姻線的雙親：使用父母中點作為虛擬來源，但不新增或改寫關係資料。
- 所有安全候選都失敗：不移動既有人物，採距離家庭外框最近的側邊走廊，並保證端點不突出。
- 拖曳校正候選被占用：不校正位置，改採最佳退化路徑。
- 規劃器輸出不符合有限數值或端點不變量：使用目前可預測的 pairwise L 型 fallback，且測試必須能捕捉該情況。
- 不允許無界迴圈或依像素逐格搜尋；候選數為常數級。

## 9. History 與互動狀態

- 拖曳起點快照、吸附、最多 60px 的安全校正及最終位置合併為一筆 history。
- `Alt` 只停用額外安全校正，不停用使用者原本的拖曳位置與最佳走線。
- 微拖曳 `<3px` 仍視為點擊，不進行位置校正或 history 寫入。
- `Escape`、失焦、工具切換與 Undo／Redo 必須清除走線預覽及建議校正，不留下 ghost 或輔助線。
- 快速建立父母的兩位人物與三條關係仍是單一原子提交。

## 10. 測試與驗收

### 10.1 純邏輯測試

建立固定輸入 fixture，驗證規劃器：

- 標準雙親單一子女。
- 長姓名與多行備註但中央走廊未被實際占用。
- 中央走廊被人物占用，左右側邊候選選擇。
- 父母與子女同列。
- 子女被拖到父母上方。
- 一位父母高、一位父母低的非對稱配置。
- 多子女、子女跨越父母左右範圍。
- 雙胞胎、同卵雙胞胎及混合手足。
- 父母靠得過近、人物重疊及零長度幾何。
- 120px 與 180px 快速父母間距選擇。
- 所有候選失敗時的有限 fallback。
- 相同輸入重算三次結果一致。

每個 fixture 驗證路徑不變量、障礙交集、端點與確定性。

### 10.2 Playwright 互動測試

- 實際拖曳人物至危險位置，確認預覽、最多 60px 校正與一次 Undo。
- `Alt` 放開保留精確 X。
- 快速建立父母在空白與擁擠列中的 120／180px 選擇。
- 既有人物座標在快速建立父母後保持不變。
- 縮放和平移後仍可點選實際顯示的家庭線。
- 失焦、Escape、工具切換後預覽狀態清空。
- PNG、JPEG、SVG、PDF 不包含校正提示，且與螢幕正式線路一致。

### 10.3 視覺與回歸測試

- 保留目前 16 張 golden：未觸發新路由的既有 fixture 必須維持 `diffPixels=0`。若既有 fixture 因本功能而產生預期幾何差異，須逐張審核、記錄變更原因並驗證線條顏色取樣完全不變；另新增專屬 routing golden，不以批次覆寫基準掩蓋差異。
- 新增亂放、同列、反向、父母擁擠、長備註及側邊繞行視覺 fixture。
- 完整執行拖曳、婚姻幾何、同住框／生活圈、子女線、雙胞胎、鉛筆、匯出與離線部署回歸。
- 240 人／338 條混合關係壓力圖單次 render 目標小於 50ms，且不可有無界搜尋。
- 根目錄、`geno/`、`refactor/app/` 的新增 planner、`app.js`、`canvas.js` 與相關 HTML 引用必須同步；既有三副本 MD5 規則維持。

## 11. 驗收完成條件

1. 使用者指定的 B 方案操作行為全部實作。
2. 已知突出、回折與快速父母壓縮案例皆有先紅後綠的永久測試。
3. 新增路徑規劃器為純計算元件，`drawFamilies()` 不再自行決策同一份幾何。
4. 所有測試與 release gate 通過，無 console／page error。
5. 原有關係線顏色與臨床符號未修改。
6. 功能只提交到 `codex/genogram-ux-drawing-optimization`，未經使用者確認不得合併 `main`。
